# Reference fixtures

## Colocalization reference fixtures

`colocalization_cellprofiler_reference.json` contains static outputs from actual
CellProfiler 4.2.8 modules for float32 threshold boundaries and object-set RWC
ranking. Inputs, normalization and dependency versions are recorded in the file.
The regression tests consume only this JSON; CellProfiler is not a test dependency.
The float32 boundary outputs remain historical CellProfiler evidence. The explicit
opt-in float64 policy checks CPM against independent scalar-double arithmetic on
the same stored float32 inputs and asserts its intentional departure. Default/input
mode retains historical boundary membership (Manders' final float32 division
rounding is tested separately from CP's double-valued coefficient). The fixture
has not been rewritten to conceal differences.

CellProfiler-dependent regeneration lives in **cpm_benchmark**, not cp_measure:
[generator](https://github.com/afermg/cpm_benchmark/blob/fe22662b38ab31649b4855c8453bc3c976210b6a/benchmarks/make_colocalization_reference.py)
and [pinned-environment instructions](https://github.com/afermg/cpm_benchmark/blob/fe22662b38ab31649b4855c8453bc3c976210b6a/docs/equivalent-pipeline.md#regenerating-cp_measure-colocalization-references).

## Pre-policy granularity fixture

`granularity_input_precision_reference.json` records the NumPy and Numba outputs
separately at main commit `8513bf33a17f78c056ca1891ba485b2d7c80e2f7`, immediately
before #129. The full uint16 image, float32 normalization and measurement settings
are embedded. It checks preservation of default/`precision="input"` behavior; it is
**not** a CellProfiler or cross-backend parity oracle. The Numba entries were set
to the NumPy values once Numba kept float32 backgrounds in float32 (#125), which
made the two backends agree bit for bit on it. Float64-mode tests instead use
explicitly widened reference inputs. No live CellProfiler dependency is needed.

`granularity_float32_cellprofiler_reference.json` holds CellProfiler 4.2.8
granularity outputs for float32 inputs (#125); its generator lives outside this
repository, as for the other CellProfiler references.

## Costes reference fixtures

`costes_cellprofiler_reference.json` contains 18 cases: three fixed synthetic
background-plus-signal pairs, two acquisition grids (255 and 65535), and three
search modes (Faster, Fast, Accurate).

Thresholds were generated by the **unmodified method ASTs** of
`MeasureColocalization.linear_costes` and `bisection_costes` in CellProfiler
commit `450abdc2eaa0332cb6d1d4aaed4bf0a4b843368d`:

https://github.com/CellProfiler/CellProfiler/blob/450abdc2eaa0332cb6d1d4aaed4bf0a4b843368d/src/frontend/cellprofiler/modules/measurecolocalization.py

SHA256 of the upstream file:
`4dedd8faf2ff1fc78f1777be517c7318420293f691e13de81888dd92b2e677f7`.

The generator verifies that hash and executes only the two inspected methods,
with NumPy/SciPy and a minimal settings holder. It does **not** import or run the
CellProfiler application. Expected coefficients apply its strict joint `>`
numerator and individual `>=` denominator convention to the reference thresholds.
These coefficient formulas are separate calculations, not a full upstream run.
The source is not modified or vendored; CellProfiler's license applies to it.

To regenerate into a new file after downloading that source:

```bash
python test/make_costes_reference.py --source /path/to/measurecolocalization.py --out /path/to/new-fixtures.json
```

CI reads the small JSON fixture; no download or CellProfiler install is needed.
Both thresholds and coefficients are compared with rtol=1e-10, atol=1e-12.
Separate tests cover scale conversion and undefined inputs. Guards intentionally
differ from upstream for constant, insufficient or nonfinite subsets: warnings
and NaNs replace accidental endpoints or stale-bound convergence.

**Scope:** parity of these threshold routines on these fixtures, not validation
of all datasets, biology, significance or the full CellProfiler pipeline.
In particular, cp_measure fits each object separately. CellProfiler's object
workflow obtains thresholds from the image and then measures objects; that
existing scope difference is not changed by this patch.
