Status: candidate prepared from `180eb15b43000a0edb3049d7c6ea4acf1e7c83df`.

## Release-note draft

### Faster batched profile generation

- The public featurizer dispatches whole batches across fields, channels and
  channel pairs. Numba backends share per-mask preparation and schedule work on
  threads rather than repeatedly entering single-image functions.
- Intensity, texture, geometry, radial features, granularity and colocalization
  support the expanded batch execution. Granularity also has compiled 3D paths.
- Fused Numba Costes uses exact pixel-entry thresholds and bounded grid statistics
  for large positive-slope objects. This is chiefly a Faster-mode optimization
  for large regions, not a promise of gains for typical small cells.
- Numba remains optional: `pip install 'cp-measure[numba]'`, then call
  `cp_measure.set_accelerator('numba')` before configuring measurements.
  NumPy/SciPy remains the default backend. Initial JIT compilation and cache
  behavior are separate from warmed throughput; larger batches can use more RAM.

### Compatibility and correctness

- Explicit Costes scope/precision, RWC object-set ranking and legacy Zernike
  boundary options support CellProfiler-oriented workflows. See the complete
  [parameter recipe](../measurement-notes.md#matching-cellprofiler).
- Default Zernike boundaries are translation-stable. Zero-signal granularity
  returns NaN rather than an epsilon-floor-derived number. Both changes have
  opt-in historical behavior.
- Float32 colocalization uses compiled paths where supported; sums may differ
  at floating-point rounding precision. `scipy_ties=True` restores SciPy's
  near-boundary Costes decisions when required.
- Fixes cover granularity edge padding and dtype behavior, nonfinite intensity
  inputs, float16 radial Zernike input, and the missing advanced 3D moments.

### Upgrade notes

Despite its patch version, this release contains API and numerical changes:

- Colocalization label functions return 1D float64 NumPy arrays instead of lists.
- Intensity requires matching image and mask shapes; intentional broadcasting
  must be explicit.
- Advanced 3D size/shape adds 12 columns (212 → 224 features).
- Zernike boundaries, zero-signal granularity and tied maximum-intensity locations
  can differ from historical outputs. See [the changelog](../../CHANGELOG.md).

## Benchmark report

The report is being prepared in [cpm_benchmark](https://github.com/afermg/cpm_benchmark),
not in the production package. It compares the release candidate's NumPy and
Numba backends with native headless CellProfiler 4.2.8:

1. Full profile generation on 300 real-image fields, with all public featurizer
   families, including Costes, five channels and three compartments.
2. Colocalization separately, after the complete profile comparison.
3. Two parameter policies: fully CellProfiler-matched compatibility options,
   and current cp_measure default measurement semantics with the same pipeline
   workload settings and acquisition scale.

NumPy means the NumPy backend of this candidate, not an old cp_measure release.
Compatibility paths can fall back to reference code, so default Numba timings
must not be presented as CellProfiler-equivalent speedups. Report numerical and
nonfinite disagreements separately from speed. The benchmark excludes
segmentation, GUI lifecycle and the original pipeline's unrelated modules.

No new release-wide speedup claim is made until these measurements finish.

## Publishing checklist

- [ ] Finish and review both benchmark policies and the numerical comparison.
- [ ] Link the final benchmark report and add only supported performance claims.
- [ ] Merge the release-preparation PR after its checks pass.
- [ ] Recheck the chosen release commit and build the final artifacts from it.
- [ ] With publishing approval, tag that commit `v0.4.1` and publish the GitHub release.
- [ ] Confirm the trusted-publishing workflow uploaded version 0.4.1 to PyPI.

Versioning is tag-derived through hatch-vcs; no source version constant needs a
manual bump. `SETUPTOOLS_SCM_PRETEND_VERSION=0.4.1 uv build` verifies candidate
artifact metadata without prematurely creating or pushing a release tag.
Publishing a GitHub release triggers `.github/workflows/release.yaml` and a PyPI
upload. A draft/preparation PR does not publish a package.
